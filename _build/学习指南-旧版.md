## 第 1 讲 · 全局地图：这份报告到底在主张什么

**要回答的问题**：为什么 NVIDIA 要把"预测未来画面"和"输出动作"放进同一个模型？这和 VLA 有什么本质区别？

**核心主张（Sec. 1，p3）**：通用机器人基础模型必须能从异构物理经验中学习、用极少任务监督获得新能力、通过交互改进、并让上层智能体调用。论文认为，满足这些要求的模型不仅要学"机器人怎么动"，还要学"动作如何改变物理世界"。于是提出 **world-action model（WAM，世界-动作模型）**：联合预测未来视觉观测与具身动作。

**四个主张性贡献**（Sec. 1 末段，p3）：
1. 开箱即用的跨任务、跨本体操作能力；
2. 极少演示即可快速适配，RL 进一步提升可靠性；
3. **x-adapt（跨本体适配）**：把某本体的物理知识迁移到另一本体；
4. 智能体化：code-as-policy 的技能组合与故障恢复 + 通过 WAM API 做视觉引导。

**架构一句话**（Sec. 2，p5）：以 Cosmos-Predict2.5-2B 视频扩散 Transformer 为骨干，视频、状态、动作被 token 化成一条序列，由同一个 2B 参数 Transformer 处理；用流匹配（flow matching）在"未来视频潜变量"和"动作"上联合训练。

**为什么这不是"更大的 VLA"**：VLA 通常以"观测→动作"的判别式映射为主，视觉理解是辅助；WAM 把未来视频生成当作与动作同等的一等目标。关键在于注意力结构：**动作 token 可以 attend 到正在生成的未来帧 token**，所以"动作能跟随模型想象出的未来"。这句话是全文的技术支点，第 2 讲要回到原文验证它。

**自测题**
1. 用一句话说清 WAM 与 VLA 在训练目标上的差别。
2. 论文说"仅靠扩大演示数据集无法解决规模化机器人智能"，它列了哪几条理由？
3. GR00T 2 Turbo 存在的根本约束是什么（不是"更快"，而是哪个物理约束）？
4. 论文的四个 contribution 中，哪一个最像"科学主张"而非"工程能力"？
5. 为什么"预测未来"能让**没有动作标签的人类视频**变成训练信号？

**常见误读**：把 WAM 理解成"世界模型 + 策略网络"两个模块。原文是一个模型、一条序列、两个损失，不是两个网络拼起来。

## 第 2 讲 · 架构解剖：一条序列里的视频、状态与动作

**精读**：p5（Sec. 2 的 Architecture 段）+ 附录 I.1（推理加速）+ Tab. 27（时延）。

**输入输出契约（记住这组数字，后面所有工程讨论都靠它）**
- 输入：最多 4 路相机、5 fps、224×320 图像，0.8 s 历史；机器人本体感知状态；一句自然语言指令。
- 输出：一个动作块（action chunk）+ 每路相机的未来帧预测。
- 执行方式：机器人用自己的控制器执行该块，同时计算下一块（流水线，见附录 K.5）。

**三个模态各自的编码方式**
- 视频：冻结的 Wan 2.1 视频 VAE，时间 4×、空间每维 8× 压缩；潜变量切 patch 后，每相机每潜变量帧 280 个 token；用一个学到的 view embedding 区分相机。
- 语言：冻结的 Cosmos-Reason1 视觉语言模型编码指令，Transformer 通过交叉注意力读取。
- 状态与动作：小的**本体专用 MLP** 映射进 Transformer 宽度，本体专用 decoder 映射回动作。

**注意力流向（第 1 讲那句"技术支点"的原文依据）**：视频 token 在时间与相机之间互相 attend；**动作 token attend 到全部视频 token，包括正在生成的未来帧**。所以动作不是从当前帧回归出来的，而是在"已经想象出的未来"条件下生成。

**训练目标**：对未来视频潜变量与动作做流匹配，各一个损失。推理时去噪步数很少：视频 1–2 步，动作 2–4 步（部署配置）。

**Turbo 的取舍**：换用 Wan 2.2 VAE，空间压缩从 8× 提到 16×，潜变量网格小 4 倍；潜变量输入输出投影适配新 VAE，动作时域不变。代价见 p26：YAM 掉 6.7 个点，灵巧任务成功率减半（68.6%→34.3%）。论文明确说"这个比较没有隔离出原因"——这是一个诚实的、值得学的措辞。

**自测题**
1. 280 个 token/潜变量帧/相机 是怎么来的？为什么 view embedding 是必要的？
2. 为什么语言用冻结 VLM + 交叉注意力，而不是把语言 token 拼进主序列？
3. 动作 token 与视频 token 的注意力是双向还是单向？这个方向决定了什么能力？
4. 流匹配相比扩散的采样步数优势在这里体现在哪两个数字上？

## 第 3 讲 · 预训练三阶段与数据配比

**精读**：p14–16（Sec. 4.1–4.2）、图 10、附录 C。

**三阶段预训练（Sec. 4.1）**
1. **单视角视频预训练**：把视频模型适配到具身视觉经验（第一人称人类视频 + 机器人数据），只预测未来视频。目的是先建立"具身交互的视觉动力学先验"。
2. **多视角视频-动作训练**：加本体专用的状态/动作模块，联合训练视频与动作；机器人轨迹提供本体动作监督，人类演示提供**手部姿态轨迹**作为动作监督；动作损失只在有有效动作监督时施加。
3. **机器人加权训练**：继续联合训练，但提高机器人（尤其 YAM）权重，把模型压到机器人可执行的动作空间上。

**三种数据的分工（这张表要背下来）**

| 数据源 | 规模（报告给出） | 解决什么 |
|---|---|---|
| Human-1M（第一人称人类视频） | 402,730 小时 / 约 1,375 万 episode / 51,500 名采集者 / 123,000 个场景（从 100 万小时数据集中过滤） | 覆盖度：物体、可供性、任务、场景多样性 |
| 实验室人类数据 | 3,000 小时，对齐机器人相机视角与演示速度 | 缩小视觉差距与运动速度差距 |
| UMI-10K（手持夹爪） | 942k episode / 10,184 小时 / 2,897 任务 / 356 类物体 / 49 项技能 | 与机器人兼容的动作表征 + 任务聚焦；含反事实配对以改善指令跟随 |
| 遥操作 | 23.5k 小时 / 116 万 episode（YAM 18.7k h、Sharpa 2.9k h、Wuji 1.3k h、G1 275 h、DROID 单臂 Franka） | 把模型锚定到具体本体与可执行动作 |

**最值得学的一个实验（图 10）**：固定架构、配方与后训练数据，只改人类视频预训练比例 0%/1%/10%/100%，在 72 个 Dexter 任务上评测。真机成功率 18%→41%，视频 rollout 成功率 30%→51%，且 100% 处**没有饱和**。作者的结论很克制："至少说明其中一种兑换率是正的"。

**Flora 数据引擎（Sec. 4.2.4）**：三个模型分别做动作边界切分、给每段动作生成自包含祈使句指令、生成结果/密集/评分制奖励；WGO-Bench 时间分割 F1 50.3，次优 GPT-6 Astra 46.0。

## 第 4 讲 · 能力证据链：五个能力，五种相对基准

**精读**：p6–13（Sec. 3），按需查附录 A（Fast-Adapt）、B（X-Adapt）、F（RL）、G（Agentic）、H（Loco-Manipulation）。

读这一讲的核心训练是：**每看到一个百分比，先问"相对于谁、在什么任务集、多少试次"**。

**4.1 Fast-Adapt（Sec. 3.1，p6–8）**
- 零样本：Dexter（Tianji 机器人 + Sharpa 双手，每只手 22 DoF），50 个任务**完全不在 Dexter 自身数据里**，只出现在 YAM 夹爪数据、人类视频或两者中。开箱成功率 40%，50 个任务里 40 个至少成功一次。
- 少样本：每个任务 1 条遥操作演示 → 71%；5 条（不到 3 分钟机器人数据）→ 95%，其中 37/50 每个试次都成功。
- **必须注意的方法学细节**：这 50 个任务是"模型用 5 条演示就能学会（≥80% 成功）"的子集，所以 5-shot 的高分**部分是构造出来的**（原文自己写了 "partly by construction"）。
- 适配成本：LoRA 微调约 30 分钟，单张 RTX 5090；适配器可合并进权重，服务方式与预训练模型一致。
- 长时序：YAM 六任务平均成功率 71.7%，基线最高 12.5%；灵巧手七任务 68.6%，GR00T 1.7 与 π0.5 最高 0.7%。

**4.2 X-Adapt（Sec. 3.2，p8–9）—— 全文最强也最需要审视的主张**
四条"不用目标机器人遥操作"的采集路线：

| 路线 | 设备 | 关键机制 | 代表结果 |
|---|---|---|---|
| 人类 → 灵巧手 | 动作捕捉手套 | 头+腕相机录制，离线重定向到手，与目标机器人 play data 联合训练 | 某任务上"无遥操作"胜过"有 10 条遥操作但无跨本体预训练"的基线 |
| DexUMI → 灵巧手 | 外骨骼（复刻关节与接触面，按手的触觉格式记录指尖力） | 从力记录学会同时预测施加的力，手的刚度随之调整 | 剥香蕉/拧罐 60–80%；擦载玻片 60%、传送带抓取抛掷 65% |
| UMI → 平行夹爪（YAM） | 手持夹爪 | 相机几何与动作空间对齐 + 目标机器人 play data | 玩具装配 60%、板件拆解 50%、传送带分拣 86% 物品；10–20 条演示即可端到端成功 |
| 单条人类视频 → 仿真 → 真机 | 仿真 + RL 专家 | 重建物体与手-物运动，训 RL 专家，在视觉随机化 rollout 上微调 | 钉钉子 9/10；基线全部 0 |

统一配方（这句话要能复述）：**演示指定"任务"，目标机器人的 task-agnostic play data 指定"本体"，跨本体预训练把两者接起来**。DexUMI 是例外——它复刻了目标手，所以那只手上不需要机器人 play data。

**4.3 RL 后训练（Sec. 3.3，p9–10）**
四个富接触精密任务，用 GRPO + CPS 采样噪声（只给动作去噪加噪，视频去噪保持确定）+ GRPO 诱导的自我模仿（在成功的 GRPO rollout 上再训练）。成功率 88%/98%/94%/96%，SFT 为 40–76%。残差 RL 也能提升但不改主干模型。

**4.4 Agentic（Sec. 3.4，p10–13）**
分工一句话：**智能体决定"做什么"，GR00T 2 决定"怎么做"**。四种支持方式：Augment（任务级程序调用）、Assist（监控并用 CaP 技能修复状态）、Guide（WAM API 视觉引导）、Improve（AutoRL 智能体用约 35 天在仿真里迭代出 RL 配方的基础）。
- 仿真榜：RoboCasa365 88.0%、RoboDojo 75.8%（2026-11-06 时点两个榜首）。
- 真机乱堆场景（每次试验前把零件随机倒在桌上）：SFT 23/100 → +DAgger 84/71/78 → +智能体 98/97/97。
- 视觉引导：短时序基准均值 76.8% vs 纯语言引导 44.2%；长时序 53.3% vs 1.7%。

**4.5 人形移动操作（Sec. 3.5，p13）**
三级栈：S2（可选推理模型，1 Hz 出任务与提示）→ S1（GR00T 2 Turbo，1 Hz 出 1.6 s 全身动作块，80 个潜变量 token + 夹爪开度）→ S0（SONIC 全身控制器，50 Hz 解成关节目标）→ PD 控制 1000 Hz。S1 跑在机载 Jetson AGX Thor，S0 在 Jetson Orin NX。爆米花服务 48/48，GR00T 1.7 为 83.3%。

## 第 5 讲 · 评测方法论：这一章比正文更值得学

**精读**：p16–17（Sec. 4.3）、附录 D 全章（尤其 D.1、D.4、D.7）。

**问题**：真机评测很贵，但如果结果不可比，几个月的评测就白做。**绝对成功率不可比**——它随工位、操作员、硬件、日期漂移。

**解法：盲测 A/B 配对比较**
- 一次 trial 在同一场景、同一操作员、几分钟内以随机顺序跑 2–4 个 checkpoint，漂移被共享从而在比较中抵消。
- GearArena 把每次 trial 汇总：快照时 195 个 campaign、16,044 个已评分 episode、11,767 次两两比较、10 个 YAM 工位、20+ 操作员、2026 年 7–11 月、71 个 checkpoint。
- 每对 checkpoint 构成一次比较，由操作员的显式排序决定（同分算平局）；用 Bradley-Terry 模型联合拟合所有比较得到 Elo；置信区间用**按任务重采样**的 bootstrap（不是按 trial——独立单位是任务）。
- 新 checkpoint 先与"参考点"（榜上最高分）比较，保证所有评分在同一连通标尺上。

**结论示例**：GR00T 2 比 π0.5 高 236 Elo（95% CI 171–325，期望对战胜率 80%），比 GR00T 1.7 高 95 Elo（CI 50–148）；四个月内当前套件最优 checkpoint 爬升 206 Elo。仿真复现 Elo 的 Pearson r = 0.93。

**必须一起读的限制（D.7 与 p27）**
- 独立单位是任务而非 trial；30–35% 的比较是平局。
- 区分 95% 与 99% 成功率需要约 285 个 trial/policy；99% 与 99.9% 需要 1000+。
- 任务设计本身是主观的：全都能过的任务归档、全都过不了的任务搁置。

## 第 6 讲 · 部署、仿真与基础设施

**精读**：p20–26（Sec. 4.5–4.7）、附录 I（加速）、J（仿真）、K（基础设施）。

**时延预算（工程上最硬的约束）**
- GR00T 2 为 Dexter 预测一个动作块：RTX 5090 工作站上中位 153 ms。
- Turbo 为 G1 人形预测：机载 Jetson Thor 上中位 124 ms。
- Turbo 与 GR00T 2 在技能上统计不可区分，但每次服务调用快约 3 倍（52 vs 171 ms）。

**三个加速方向（附录 I）**：模型推理加速（去噪步数、VAE、编译）、策略平滑性、超越演示的任务吞吐（相位条件重定时把三个灵巧任务的平均完成时间缩短 15–26%）。

**仿真（附录 J）**：real-to-sim 生成高保真任务；用仿真加速开发；仿真基准作为代理评测（25 个 YAM 任务上，仿真预测 14 个通用 checkpoint 的真机任务进度，Pearson 0.93）。但要警惕：对富接触装配、对会利用仿真误差的 RL 策略，这个相关性尚未验证。

**基础设施（附录 K，报告里少见的实数据）**
- 预训练用 **1,024 张 GB300**；数据管线每月处理 PB 级输入。

## 第 7 讲 · 批判性精读与开放问题

**精读**：p26–28（Sec. 5 全章）。这是全文信息密度最高的三页。

论文自己把开放问题分成六组，每组都从"让这件事变难的基本约束"出发——这个写法本身值得模仿。

| 组 | 基本约束 | 论文承认的空白 |
|---|---|---|
| 模型 | 策略从"观测主导"的数据里学，却要按物理世界的速率行动 | 该预测未来的哪些方面、什么分辨率与时长；预测是训练信号还是推理时的想象；记忆应当是"结构化的"而非更长；力/触觉只作为输出、不作为输入 |
| 数据 | 每小时机器人数据都要机器人和操作员 | 三种数据之间**没有兑换率**；失败与恢复数据稀缺；缺"演示执行质量"标签 |
| 评测 | 成功率是二项估计，不确定度只随 √n 收缩 | 部署尺度的代理评测；自动验证（8 次失败中有 3 次是螺钉没拧到底而模型和智能体都判成功）；"达到目标可靠性的成本"从未被报告 |
| 硬件 | 模型只能学硬件允许人演示、传感器记录、机器人重复的东西 | 遥操作演示不了快速定向动作（如传送带抛掷）；主张机器人与采集设备一起设计 |

| 部署 | 机器人的价值由"多久需要一个人、多快、是否安全"决定 | 常规化改进闭环；跨层级时延（智能体一轮中位 7.5 s，策略一次调用约 0.6 s，机器人中位 38% 的 episode 时间在等智能体）；安全的物理动作检查 |
